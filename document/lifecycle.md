# 生命周期与失败语义

## 状态机

```prodoc-flow
graph LR
  New[已注册] -->|mount| Mounted[已挂载]
  Mounted -->|unmount| Unmounted[已卸下]
  Unmounted -->|mount| Mounted
  Mounted -->|依赖消失 + reconcile| Pending[待挂载 / pending]
  Pending -->|依赖回来 + reconcile| Mounted
  Mounted -->|mount 失败| Failed[失败]
```

进程外插件还有一层**进程**状态（与上面的"挂载状态"正交）：

| `state` | 含义 |
|---|---|
| `pending` | 进程在起，还没握手完 |
| `ready` | 握手成功、贡献已注册 |
| `draining` | 收到排空指令，等在途调用结束 |
| `stopped` | 正常退出 |
| `failed` | 崩溃/启动失败（按 backoff 重试，超过熔断次数后停） |

`enabled = true` 而 `state = failed` 是"配置开着、进程起不来"，和"用户关掉了"
是两件事，宿主必须能分开显示。

## 失败语义一览

| 失败 | 结果 | 会不会自动恢复 |
|---|---|---|
| 依赖缺失 | 拒绝挂载，`pending` 记下缺的键 | 会（`reconcile`，依赖到位即挂） |
| `mount` 闭包返回 `Err` | 挂载失败，**不进 pending** | 不会（这是插件自己的 bug，自动重试会变成静默失败循环） |
| 子进程启动失败 | backoff 重试，200ms×2 上限 2s，5 次后熔断 | 有限次 |
| 子进程崩溃 | 同上，已就绪的贡献会失效、重连后重建 | 有限次 |
| 调用超时 | 该次调用失败，插件不受影响 | — |
| 事件投递返回 `Err` | 计数，不卸载 | — |
| 事件投递重入 | 内层丢弃 + 记一次失败 | — |

## 两处刻意的"不自动恢复"

**挂载闭包报错不进 pending。** 缺依赖是"还没轮到"，闭包报错是"它自己坏了"。
把后者也塞进 pending，就会变成每来一次服务变动就重试一次失败插件——错误被
重试掩盖，日志变成刷屏。

**事件投递失败不卸载插件。** 事件是观察通道。一个插件对某条通知处理不了，
不该因此丢掉它已经挂载的所有能力。

## 热替换（进程外）

```rust
handle.upgrade(new_config, timeout).await?;
```

顺序是：新进程起来 → 握手 `Ready` → **原子切流量** → 老进程 `Drain` → 退出。
新进程没就绪就不切（失败保老，可回滚）。这条路径同时被"配置代际"验证覆盖——
替换后调用打到的是新实例。

## 卸载顺序

1. 该插件名下的**子作用域先卸载**（递归，子先于父）——否则父的服务表先撤，
   子插件的 `unmount` 可能还要用父的服务；
2. 该插件 `mount` 返回的 `Disposer` **逆序**撤销；
3. `Plugin::unmount()`（disposer 之外的清理：关文件、停线程）。

第 3 步在 v0.6 之前**从未被调用过**——注册表撤完 disposer 就返回了。这是一个
典型的"接口存在但没人调"的死代码，已修。
