# 边界与纪律

这个仓库的价值一半来自"能做什么"，另一半来自**明确不做什么**——后者由门禁
测试守着，而不是靠自觉。

## 一、零领域依赖

`echo-context` / `echo-plugin` / `echo-plugin-api` / `echo-plugin-loader` /
`echo-plugin-host` / `echo-plugin-sdk` 都**不许**依赖任何应用 crate，也不许
出现 `tool` / `session` / `agent` 这类词汇作为类型或服务键。

`crates/framework-gates` 会检查：框架 crate 的 `Cargo.toml` 依赖表里没有
指向宿主的项。这条门禁是"这套框架能被别的项目用"的可执行证明——一旦有人为了
方便在框架里 `use` 宿主的类型，门禁立刻红。

### 为什么这么严

**反例**：v0.2 时 `MountContext` 里有两个字段 `tools` / `skills`，各配一个
`PluginToolSink` / `PluginSkillSink` trait，"给未来的工具插件预留接缝"。
审计发现：全仓 `mount` 闭包都是 `|_ctx| Ok(vec![])`、`register_tool` 零调用点、
`SkillSink` 从未实例化。**预留的接缝一次都没用过，却把两个业务词汇写进了框架**。
v0.3 删除。

教训：**给未来的预留，几乎总是错的**。真正需要时会加，那时也知道该长什么样。

## 二、零全局态

框架**不导出**进程级单例表。想表达"这个宿主里只有一份"，用 `Ctx`：它是显式
注入的，可以有任意多份、互不干扰。

原 `echo-context::kernel`（`TypeId` 键控的全局单例表）在 v0.3 搬到了宿主侧。
原因很具体：框架导出全局态，就等于宣称"一个进程只能有一套宿主"——而那正好
破坏了"这框架能被任何 Rust 应用使用"这个复用前提。

## 三、名字 + 存在性，而不是类型

四处都是名字：服务键、插件 id、事件名、作用域父链。框架只校验**存在性**，
从不要求跨插件的 Rust 类型。

三个直接后果：

| 后果 | 是缺陷还是选择 |
|---|---|
| 拼错的服务键只在运行期报错 | 选择。补偿是错误里带 `available` 全量清单 |
| 事件载荷是自由 JSON，没有 schema 校验 | 选择。schema 是宿主与插件的契约 |
| 插件之间不能直接调用彼此的 Rust 方法 | 选择。能调就不再有"可独立替换" |

**如果一定要类型**，正确做法是在宿主侧做适配层（EchoAgent 的
`echo-plugin-adapter` 就是把协议里的 `ToolContribution` 翻译成宿主的 `Tool`
trait）——适配层可以认识业务，框架不行。

## 四、不做的三件事

**不锁语言。** 协议是 JSON 帧，不是 Rust ABI。所以有了纯 Python 插件示例与
它的 3 项测试；也所以框架不能要求"插件必须实现某个 trait"。

**不做权限模型。** 进程外能靠 `env_clear` + `rlimit` 做隔离（这是**资源**
隔离，不是权限），进程内则假定插件可信。完整的 capabilities 声明与宿主中介
（fs / net / proc）没有做——它是"不可信第三方插件"这个场景才需要的，而那需要
先有 wasm 沙箱轨。

**不做业务持久化。** 插件状态存哪、格式怎么迁移，是插件与宿主的事。框架只提供
"注册可撤销"这一条纪律。

## 五、判定"这段代码该不该进框架"

三个问题，任一为"是"就不该进：

1. **它换了个应用还成立吗？** —— "工具调用"不成立，"按名字找服务"成立。
2. **删掉它，机制还完整吗？** —— 预留的未来接缝 → 删（见上面的反例）。
3. **它要求框架认识某个具体类型吗？** —— 是就下沉到宿主侧适配层。

## 六、当前已知的边界

| 边界 | 状态 |
|---|---|
| `dylib` 轨 | 未实现（Rust 无稳定 ABI；若做优先评估 `stabby`） |
| `wasm` 轨 | 未实现（沙箱需求明确后再评估 wasmtime / extism） |
| 声明式注入的类型化 | 不做（见 §三） |
| 就绪等待 vs 立即失败 | 两种都有：`mount` 立即校验，`mount_when_ready` 等待 |
| 状态迁移协议（`export_state` / `import_state`） | 未实现（可选） |
| 多插件共享预算 | 未实现（`rlimit` 管单个插件失控；cgroup 级共享未做，收益/成本不划算） |
